## Workflow rules

1. Edit sources → `node .build/newtracker/build.mjs` → inspect `git diff index.html` and confirm insertions/deletions are confined to the intended scopes before reporting done.
2. HTML entities: in template/build strings use numeric entities for curly quotes, dashes, ± (`&#177;`) etc. — the file is ASCII-styled.
3. `write_file` refuses paths outside the workspace when BOGAN approval mode is active — temporary harnesses/scripts must live inside the repo (e.g. a `.tmp-check/` dir) and be deleted before commit.
4. Reader-mode/no-JS content lives in `template.html`'s STATIC_SUMMARY region, generated by `buildStaticSummary()` in `build.mjs`; the app root carries `class="supplemental"` deliberately (reader-engine signal — see reader-mode-friendly-spa skill). Don't remove it or move the article inside `#root`.
5. `data/resolve-political-monitor.csv` is **not** part of the gen-data pipeline — it's maintained by `node .build/extract-resolve-rpm.mjs` (lives in `.build/`, fetches/decrypts the live SMH Resolve tracker, merges with upstream-defect repairs). Refresh it standalone; see the resolve-monitor-extraction skill. It cross-checks `polls.json` via `.build/check-resolve-vs-tracker.mjs` (read-only) and `.build/backfill-resolve-approval.mjs`.

6. Any edit to `data/polls.json` must exit through the same gate: run `node .build/newtracker/validate.mjs` standalone (even though build.mjs calls it — fail fast) and confirm clean before committing. Deliberate exceptions are declared in-data (`sumNote` / `pollsterRules`), never left as unexplained failures.

7. Multi-line git commit messages: **do not** use `git commit -m "$(cat <<'EOF' …)"` through the harness — the shell wrapper's double-quote nesting breaks it out mid-quote. A **plain `-m` with literal newlines inside the quoted string works** (used for the launchd automation commit); the heredoc command-substitution form is the only broken one. For very long messages, `write_file` a message to `.git/COMMIT_MSG.tmp`, `git commit -F .git/COMMIT_MSG.tmp && rm .git/COMMIT_MSG.tmp && git push` in one step (temp created and removed in the same step).
8. **Copy that promises hover must be input-conditional** — touch devices can't hover, and hover-driven UI there degrades differently (e.g. the past-cycles chips *toggle* a term's line on tap instead of highlighting it; the slick `setHi` highlight only flashes). Pattern in the view sources (see `CANT_HOVER` beside `PastCyclesView` in the tabbed-views asset): `const CANT_HOVER = window.matchMedia("(hover: none)").matches;` — the **primary input media query**, not a touchscreen sniff — then render the tap/toggle wording as the ternary branch and keep pointer wording for mouse users. The accuracy panel's hint now does this too: `houses — {CANT_HOVER ? "tap" : "hover"} one for its figure` (lowercase branch mid-sentence). `CANT_HOVER` is module-level per asset (`d1a1d215` ~line 1106, plus a separate copy in `73de0c58` for the lede); a component lexically *above* the const may still reference it, since JSX bodies only run after module evaluation — no temporal-dead-zone trap.
9. **Editorial copy is mirrored twice** — the About / Reading-the-charts / accuracy-caveat / Sources / disclaimer paragraphs exist BOTH in `build.mjs`'s `buildStaticSummary()` (numeric HTML entities: `&#8212;` em dash, `&#8217;`, `&#8220;`/`&#8221;`) and in `73de0c58`'s `MethodNote` (literal JSX typography, `{" "}` hard spaces). Change one, change the other, same wording. Two traps found mid-edit: (a) JSX collapses the newline after an end-of-line expression — insert `{" "}` explicitly or the space vanishes; (b) HTML attributes (meta description etc.) take the literal `—` character, not an entity.
10. **Edit-tool hazards on the source files (assets AND build.mjs)**: (a) a literal backslash escape in source (e.g. `"...\u2013..."`) can never match an `edit`/`old_string` containing the rendered character — work around with an inline Python script (`pathlib` read/replace with `assert src.count(old) == 1` per substitution, then write back) **or anchor on an escape-free adjacent block** (confirmed inside build.mjs itself 2026-09-03: `raceLine`'s three `\u2013` literals broke every old_string quoting it; anchoring on the escape-free `};\n\nconst fav = buildFavicon();` further down inserted the edit first try). ## Verifying a UI source edit landed in the built page (grep method; learned 2026-09-01)

Babel transpiles the JSX assets with **`compact: false`** — the compiled `React.createElement` blocks inside `index.html` are **pretty-printed across many short lines**, not minified. Two consequences when checking your edit actually shipped:

- A **padded-window grep matches nothing**: `grep -oE '.{80}needle.{160}' index.html` finds zero hits even when the needle is present (it sits near a line end) — and an empty match reads exactly like "the rebuild didn't pick up my edit". This burned a verification loop during the hero-strip change (`f48f8d2`). Instead: `grep -n 'needle' index.html | cut -c1-300` for line numbers, then `read_file` with `offset`/`limit` to inspect the compiled JSX in place; plain `grep -c` counts are reliable for presence/absence.
- Non-ASCII inside JS string literals is **escaped** (`"\xB1 "` for ±, `\u2014`, `\u2026`) — grep for the escaped form (see user-level auspol-built-html-verification). Template **CSS is not transpiled**, so style rules in the built page grep verbatim (`grep -n '\.my-rule' index.html`).
- **Counting on the minified/single-line data files, and verifying the LIVE page** (learned 2026-09-02, DemosAU + Essential methodUrl legs): `grep -c` counts **lines**, so on the single-line `9f09dca2` bundle / its index.html inline copy it undercounts wildly (13 occurrences on 3 lines → reports 3). When the count itself is the check: `grep -o 'pat' <file> | wc -l` for raw occurrences, and for a field that deliberately shares values across rows verify on **unique values** — `grep -o '"methodUrl":"[^"]*<host>[^"]*"' index.html | sort -u | wc -l` (Essential leg expected 1 unique URL across 11 rows; DemosAU 7 unique) plus a row-count read off polls.json. For the post-push live check: allow ~60–75 s for the Pages deploy, and curl **https://auspoltracker.com/** — the repo CNAME. **auspol.info is NOT the site any more** (observed 2026-09-02: HTTP 301 → `auspol25.substack.com`, Cloudflare; domain repurposed) — grepping it returns the substack and reads exactly like "not deployed".

## TrendChart height system (debugging chart sizing)

Every trend chart is one `TrendChart` (toolkit `08b413e7-…js` ~line 109, default `height = 360`); the caller sets a `height={…}` prop that becomes the viewBox height H in `<svg viewBox="0 0 1000 H">` (`const VB = { W: 1000 }`, ~line 648), styled `.chart-svg { width:100%; height:auto }` (template ~line 957). **Rendered height = container width × H/1000 at every viewport — there is no `@media` or JS compensation**, so a chart that is short in viewBox units is proportionally shorter on a phone (e.g. H=250 renders ~94 px tall on a 375 px screen). When a user reports a chart "looking short on mobile", the answer is arithmetic, not a CSS bug.

Height inventory after the 2026-08-29 equalisation (commit `2b9e313`, prompted by exactly that report — leadership/direction charts were 250 with no documented reason):

- `73de0c58-…js` ~line 718 — hero 2PP `height={420}` (hero emphasis, deliberate)
- `a11e1559-…js` — Primary vote `340` (~254), Preferred PM `340` (~897), leader approval `340` (~1146), National direction `340` (~1285); Undecided `210` (~1410, minor single-line chart — raise only if asked)
- `d1a1d215-…js` — model/analysis charts `300` (~772, ~1697)

Convention to preserve: main panels all 340; deviating heights need a comment at the call site. The leadership pair sits in `.two-col.lead-grid` (2-col ≥1200 px, stacked full width below — template ~lines 710/1906; the `.dl-*` "dial" CSS is the wordmark dial, a red herring). Height is independent of yDomain/yTicks/pad/morph-comments — changing it mutates nothing else in the JSX.

Diagnostic hazards found during that investigation:

- `git log -S` (pickaxe) **times out after 120 s** on the big panels asset — use plain `git log --oneline <file>` or grep the working tree instead.
- Grepping the **built** `index.html` broadly dumps inlined base64 fonts into the output and truncates it — grep the asset **sources** under `.build/newtracker/assets/` and confirm the rebuilt file afterwards.
- A backtick inside a single-quoted grep pattern still breaks the shell wrapper — quote the pattern or grep with similar plain text.

For *whether* a chart may gain a CI ribbon / dash / dot-cloud (and the party-token/italic-"v" type rules), see the **chart-uncertainty-grammar** skill — the decision rules live in asset-code comments; this skill covers mechanics only.

## CycleChart insight-sentence naming (office-holder, not party)

User-directed rule (implemented 2026-08-29): the past-cycles insight sentence names the **sitting office-holder** on leader metrics and the **party** on vote metrics — "15 months in, **Albanese** sits N below the average **prime minister** at this point", "**Taylor** sits N above the average **opposition leader**", but "Labor … the average **government**" for primary/2pp. Mechanics:

- `gen-data.mjs` `CYC_META` (~line 1076) carries per-cycle `pm` / `oppLead`; mid-term handovers are written as **" → "-joined lists** ("Ley → Taylor", "Gillard → Rudd") with `pmSpl`/`oppSpl` (`OPP_SPLICE_ISO = 2026-02-13`); emitted `CYCLE_DEFS` keeps both fields — no data-pipeline change needed to consume them.
- In `d1a1d215-…js`, the `sitting()` helper (just above `CYC_SHAPES`, ~line 479: `s.split(" → ").pop()`) takes the last name in the list, and the CycleChart insight block (~line 775) keys subject AND peer noun off `M.key` with an `isOpp` fallback: `net → sitting(cur.pm) / "prime minister"`, `oppnet → sitting(cur.oppLead) / "opposition leader"`, else `D.PARTIES[isOpp ? cur.opp : cur.gov].name / (isOpp ? "opposition" : "government")`. Rationale (in the code comment): primary/2pp measure parties, a leader chart averages holders of an office. **The `isOpp` fallback is load-bearing**: `oppr` (the surviving opposition vote metric; `oppt` was later excised) carries `leader: "opp"` (for line labels), so a plain `isOpp → leader` ternary would print "Taylor … the average opposition leader" on a VOTE chart — key the person/office branch off `M.key === "net"/"oppnet"` explicitly.
- Verify against the **emitted** `CYCLE_DEFS` (see the JSON.parse recipe in the 9f09dca2 bullet above) — simulate `SUBJ(key)`/`NOUN(key)` against `cur = CYCLE_DEFS.find(c => c.current)` and print the sentences; expect Albanese / Taylor / Labor / Labor / **the Coalition** (five metrics post-`oppt`-excision). **Party article (user-directed 2026-08-29, reversing the same-day "bare" convention)**: LNP subjects render as "the Coalition …", Labor subjects stay bare ("Labor sits…"). Implementation: `subjParty = isOpp ? cur.opp : cur.gov`, then `(subjParty === "lnp" ? "the " : "") + D.PARTIES[subjParty].name` — the article is a party-key test, not a name test.
