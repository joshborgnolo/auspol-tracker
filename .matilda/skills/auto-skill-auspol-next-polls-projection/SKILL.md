# auspol-tracker: Next expected polls — projection, panel, ticker

Feature added 1 Sep 2026: a slot whose expected release moment passes unrecorded holds its place as red **"N days overdue"** until the poll is actually recorded — no silent roll-forward, no disappearance. Worked across `gen-data.mjs`, two asset bundles, polls.json schema, template CSS, copy, and a sim harness.

## Trace chain (top-down)

1. **`gen-data.mjs` ~§cadence (~1289–1610)** computes per-house `pollCadence` rows: `{pollster, site, last, cadence, lag, spread, spreadEarly, spreadLate, releaseDow, releaseMins, loose, skipped}`. `spreadEarly`/`spreadLate` are the MEASURED one-sided tails of the release-gap record — every dated weekday house in the 2026 record slips LATE, never early (`spreadEarly 0, spreadLate 7`; loose houses like DemosAU can have both sides non-zero). Shipped in the data asset `.build/newtracker/assets/9f09dca2-….js`. Houses are excluded ONLY by `pollsterRules[firm].stopped` (hand-declared in `data/polls.json`, schema-documented). The old `CAD_MAX_SILENT = 1.5` eviction constant is REMOVED — silence never evicts; genuinely dead houses (Fox & Hedgehog, Freshwater in Sep 2026) are flagged by hand with an explanatory note in polls.json.
2. **`skipped` = slot dates verified ABSENT at the publisher** (pollsterRules.skippedSlots, written by `.build/essential-confirm-skip.mjs` — see "Skip-confirm agent" below). npProject rolls the slot walk straight past them before any overdue/missed flags are computed — **ONE WEEK per skip for a dated house** (`field += (releaseDow != null ? 7 : cadence)*DAY`), because Essential's record only ever slips 28→35 days, never 56; undated/loose houses keep full-cadence steps. A verified-absent slot shows neither red nor "(or N days ago)" — the row just counts to the NEXT unverified slot. Seeded for Essential 2026-08-26 on 1 Sep 2026. **A slot the walk rolls past a skip lands exactly on the house's measured late step** (Essential only ever goes 28→35, so the rolled slot IS the "late alternative" a ± tail would name) — npProject therefore sets `rolled` inside the skip loop and pushes `rolled: rolled && i === 0` on the row (only the FIRST row of a walk can sit on the rolled slot), and pmLabel/dayAlt key off it (see "Skip-rolled slots" below). The same one-week-ahead slot walk is mirrored in `sim-next-polls.mjs` and in `essential-confirm-skip.mjs` (it computes the NEXT unverified slot, so the morning after a newly-skipped date passes, the cron confirms that one too — repeated weekly slips accumulate in skippedSlots).
3. **Projection runs LIVE in-browser**, not at build time: `npProject()` in **`.build/newtracker/assets/np-project.js`** (assigned there as `window.AP.nextPolls`) walks `last + n*cadence`, snaps to the week's `releaseDow` (±3-day snap), and stops a house's walk once a slot is `overdue || loose`. Horizon `NP_HORIZON_DAYS = 28` past the DATA clock (`LATEST_ISO`), not the wall clock. Untimed houses default to `NP_UNTIMED_MINS = 24*60`. **Since 220c88f the projection lives in the PLAIN asset layer** (build.mjs PLAIN list: 9f09dca2 data → ed2260de (sets `window.AP`) → np-project.js → copy-chart.js), extracted verbatim from a11e1559 so the sim evals the shipped file instead of mirroring it; DAY_MS/NP_HORIZON_DAYS/NP_UNTIMED_MINS/easternNow/spreadDays top-level consts are shared with later classic scripts via the global lexical environment (a11e1559's `DAY_MS` and 73de0c58's `easternNow()` resolve from here) — **never re-declare any of those names in a later script (duplicate top-level const = the whole second script fails to parse), and never put `export` in np-project.js** (classic script; Node-side importers eval it with `global.window = {}`, so ESM syntax would break the sim/np-score harness). It takes an opt-in `nowOverride` `{day, mins}` clock seam — the page always calls it bare, sims/scorers pass scenario clocks.

## Calendar-month rhythm (added 1 Sep 2026 — DemosAU)

Some houses poll exactly once per CALENDAR MONTH on no fixed day of it — DemosAU's five consecutive waves (Apr–Aug 2026) PUBLISHED on the 17th/22nd/22nd/13th/24th, and its full published record (from Jan 2026) runs the 9th to the 27th. Measured as an interval, the median ± spread always spills past the month's ends (DemosAU's Sep slot read "13 Sep – 5 Oct" when the wave cannot be in October at all). Chain:

1. **Declare it** in `data/polls.json`: `pollsterRules.DemosAU.release = { month: true, note: "…" }` (schema: `release.month`, described as "window is the month itself — the day-of-month range the house has actually filed on (…1st-to-last is the fallback)", "implies no weekday habit"). Not inferred — the points sit inside months well enough but nothing in the data marks the month as the unit.
2. **`gen-data.mjs`** hoists `const decl = (D.pollsterRules?.[firm] || {}).release || null` ABOVE the dated/loose gate, then `const calMonth = !!decl.month` (null-safe — the build THREW `Cannot read properties of null` at first because most houses have no `release` decl). calMonth forces `dated = false` (→ `loose: true`), `releaseDow = null`, exempts the house from the `CAD_LOOSE_MAX_REL_SPREAD` eviction, pushes `calMonth: true` onto the pollCadence row, and adds `"calendar-month rhythm"` to `declared` (panel foot: "stated from …'s own schedule rather than measured"). It ALSO emits **`calDays` = [min, max] day-of-month of `seq`** (the same published sequence the gaps were measured along — published dates wherever the unbroken dated tail is long enough, fieldwork otherwise; `seq.map(d => Number(d.slice(8,10)))`) pushed beside calMonth — nothing declares it, it re-measures every build, so an outlier widens it and a steady run keeps it narrow.
3. **`npProject` (np-project.js; was a11e1559 before the 220c88f extraction)**: a `c.calMonth` branch placed FIRST inside `cad.forEach` computes the slot: `open = Date.UTC(sy, sm, calDays ? calDays[0] : 1)`, `close = calDays ? Math.min(Date.UTC(sy, sm, calDays[1]), lastDay) : lastDay` with `lastDay = Date.UTC(sy, sm + 1, 0)` (next month's day-0 = slot month's last day — the clamp means a 29th–31st filing habit never invents a date a shorter month doesn't have; the bare 1st→last month is the fallback where calDays is absent), where `sy/sm` wrap Dec→Jan. It pushes ONE row with `spread = winHalf = (close − open)/2/DAY` and `release = (open+close)/2` — i.e. a loose window whose centre and half-span ARE the bracket — then `return`s (forEach continue). Inclusion: `open <= horizon || missed` (missed windows keep their seat like every other unrecorded slot). `missed = close < t0`. Since aef2352 the branch FIRST rolls `sm/sy` one month at a time past every entry of `c.skippedMonths` (`YYYY-MM` of the SLOT month) — see "Month-grain skip confirmations" below.
4. **NO render-layer projection special cases exist** — that's the design point. A calMonth row IS a loose row to every consumer: the panel's date span computes `release ∓ spread` back to the bracket's own first/last day; the ticker's `targetOf` counts to `release − winHalf` = the bracket's open; overdue counts and sort keys fall out of the existing loose/missed paths. The ONE d1a1d215 edit lives in LABEL VOCABULARY, not projection, and is keyed off `releaseDow == null`/`byDay`, not `r.calMonth`: an unpinned-day target whose window is open reads **"any day now"** (was "any moment now" — MOMENT is reserved for dated houses whose slot moment is due/passed today: day-scale uncertainty says "day", hour-scale says "moment"), and the `(maybe)`-suppression guard excludes BOTH phrases (`when !== "any moment now" && when !== "any day now"`). Resist any `if (r.calMonth)` in renderers all the same — the shaping is done once in the projection.
5. **`sim-next-polls.mjs` `project()`** mirrors the branch 1:1 (calDays + month-end clamp included). Expectation shapes: BEFORE the bracket opens (S1 – Tue 1 Sep, bracket 9–27 Sep) DemosAU counts "8 days" WITH the loose-house `(maybe)` and Essential's slipped slot LEADS the roll; mid-bracket (S1c – Mon 14 Sep) it reads **"any day now"** with `maybe:false`, panel "open now"; past the bracket's close the overdue count runs from the measured max-day, so Sat 10 Oct vs 27 Sep = **"13 days overdue"** (RedBridge ties at 13 and sorts first via cadence order). Cadence label says "monthly" via the generic `cadenceLabel(31)`.

Gotcha of record: the diagnostic console line in gen-data prints DemosAU's cadence/spread as measured even though they're no longer used for projection — cosmetic, but confusing when diffing build logs.

### Backfilling `published` on a historical wave — what moves and what can never

`published` is curated onto poll rows by hand (see demosau-extraction), and adding one to an OLD wave extends the house's unbroken dated publication tail BACKWARD, so the next rebuild re-derives honest numbers off a longer `seq`. Worked example (1 Sep 2026, DemosAU Jul-2025 wave gained `2025-07-09T12:24`): cadence median 31→33, `gapsUsed` 7→8, `spread` 11→16 and `spreadEarly/Late` re-measured — the recovered 184-day gap lands dead centre in a `CAD_SPREAD_TRIM`-trimmed end value exactly as that constant's own comment block foretells (the comment already discusses the 184-day gap from the fieldwork-era basis); `releaseMid`/time medians shift; `lag` stays 0 regardless (gen-data hardwires `lag: 0` for a published-basis house, so the recovered 3-day fieldwork→publication gap never surfaces). **For a calMonth house ALL of that is informational**: the shipped window is `calDays`, re-measured min/max day-of-month over the extended `seq`, and it moves ONLY if the new published date's day lies outside the previous range (Jul-25's 9th landed inside the existing [9,27] — the 9 Sep–27 Sep window stood byte-identical). Confirm with the diff, not reasoning from memory: old asset vs new should differ ONLY in that house's pollCadence line and the affected poll row; `np-score.mjs` must report "no tuple changes" (tuple identity = release/winHalf/rolled — none of those recompute from cadence/spread).

## One-sided windows (Sep 2026 phantom-date fix)

`targetOf` (ticker) and `dayAlt` (panel) must use the MEASURED one-sided early edge `spreadEarly`, not the symmetric `winHalf`. The Sep 2026 phantom: the ticker reused `winHalf` (7) as the early edge for Resolve — whose record is `spreadEarly 0 / spreadLate 7` (never early, slips a week twice) — so it counted down to a **SUN 6 SEP THAT COULDN'T HAPPEN** and out-sorted Roy Morgan's real Mon 7 Sep with "5 days". Fix: `earlyHalf = 7*Math.floor((r.spreadEarly * Math.sqrt((r.ahead||0)+1) + 3)/7)` — week-quantised like `winHalf`, drift-widened, symmetric fallback only when `spreadEarly == null`. With `spreadEarly 0` the target lands on the projected date itself (Sun 13), so the `(maybe)` hedge (`t.at - release > 7*DAY`) no longer fires — that matched the spec "navbar should JUST say … tomorrow / 6 days", no hedge.

Panel side: `dayAlt(r)` (lives right after `pmLabel` in a11e1559) mirrors the date-column's "(or Sun 20 Sep)" suffix as a day-count: `when(r.inDays) + (dayAlt(r) || "")`, non-overdue dated rows only:
- `earlyW === 0 && lateW >= 1` → ` (or ${inDays + lateW*7})` — "in 12 days (or 19)" (Resolve), "in 19 days (or 26)" (Newspoll);
- `lateW === 0 && earlyW >= 1 && inDays - earlyW*7 >= 1` → the mirrored early-side clause (long-waiting houses; the `>= 1` guard kills degenerate past/alternative phrasing — a "0 days" alternative was nonsense copy in the first draft).

## Skip-rolled slots name no alternative (the "tomorrow (or 8)" fix, 9768a87)

Reported 1 Sep 2026: Essential's card read **"Wed 2 Sep, 1 am AEST (or Wed 9 Sep) / tomorrow (or 8)"**. Root cause was a double-counted late step: the confirmed skip of 2026-08-26 had rolled the slot walk +7 to Wed 2 Sep — which already IS Essential's measured late step (29 Jul + 35 days; the gap record alternates exactly 28/35/…, **never 42/56**) — and then `pmLabel`/`dayAlt` appended a SECOND +7 tail from the row's untouched `spreadLate: 7`. The tails were naming a 42-day slot Essential has never filed (the user's report: "essential is at a 35-day or 28-day cadence, and tomorrow will be 35 days").

Fix — shaped ONCE in the projection, not per-renderer (same principle as calMonth's "NO render-layer special cases"):

1. `npProject` sets `rolled = true` inside the skip loop; the row carries **`rolled: rolled && i === 0`** (a rolled walk has exactly one rolled row — its first).
2. `pmLabel(r)`: `if (r.rolled) return "";` with a lead comment explaining why (naming " (or +1 week)" past the rolled slot doubles the one late step the record contains; stepping BACK an early week would name a date confirmed never filed).
3. `dayAlt(r)`: `if (r.rolled) return null; // the slot IS the late step - see pmLabel`.

What was deliberately NOT done: touching gen-data/spreadLate (pollCadence stays honest about the measured record — the +7 tail is truthful data, just not label-worthy after a roll), zeroing spreadLate on the row, or special-casing in the panel renderer. Un-rolled houses keep their tails exactly as before (Resolve still reads "in 12 days (or 19)"). The ticker needed nothing — it never rendered these tails. Sim blind spot fixed in the same commit: `sim-next-polls.mjs` previously mirrored `when`/`ago`/`panelWhen` but NOT `pmLabel`/`dayAlt` — precisely why the bug shipped unobserved. The sim now mirrors `npFmt` (via `D.monthName` on the shipped data asset), `spreadLabel`, `pmLabel`, `dayAlt` byte-exactly, `panelWhen` composes `when(inDays) + (dayAlt || "")`, and S1 locks BOTH sides: rolled Essential → `["", null]`; un-rolled Resolve → `[" (or Sun 20 Sep)", " (or 19)"]`.

The other off-ramp besides `stopped`: a slot verified ABSENT at the publisher. Chain: `.github/workflows/essential-update.yml` 05:02-AEST daily cron (`'2 19 * * *'`, mirrored in `.build/local.auspol.essential.plist`) → `essential-updater.sh` no-change branch → `.build/essential-confirm-skip.mjs "$STATUS_JSON"`. The update only happens when ALL of these hold, and a failed check is a silent no-op (or an explicit refusal logged for human review), never an error:

1. The extractor ran THIS sweep and exited 0, so `ESSENTIAL_STATUS {json}` is fresh evidence, not a cached state; it must carry `latest_report_date` (extractor emits it + `latest_report_title` from the newest WP `reports` post).
2. `latest_report_date < slot+1` — the publisher's index was fetched and its newest report predates the slot; positive evidence of absence. (`"changed": false` ALONE is never sufficient — a failed half-crawl also prints changed:false.)
3. It's at least **05:00 Australia/Sydney on slot+1** — computed in the Sydney frame via `Intl.DateTimeFormat` (one fixed-point offset pass), never UTC math, so AEDT doesn't move it.
4. Not already listed — idempotent.

On exit code **3** the updater validates → rebuilds → commits `data/polls.json`+`index.html` as "Confirm skipped Essential slot …" → pushes. Adding skippedSlots to OTHER houses needs an equivalent evidence source in their extractor's status line; absent that, no list entries.

## Time frame

Everything is in **Sydney wall-clock**: `scen()`-style epoch anchors = `Date.parse(day + "T00:00:00Z") + mins*60000` are SYDNEY day+minutes (the harness pins dayFloor/UTC tricks to the app's own frame). `release` is day-floored after the dow snap; `due = release + releaseMins*60000`.
