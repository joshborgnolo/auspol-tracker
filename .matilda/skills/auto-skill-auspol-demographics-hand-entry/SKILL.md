# Hand-entering a one-off wave's demographic breakdown (vote-by-group pipeline)

## The trap: `data/demographics.json` is a build artifact

`.build/demographics.mjs` rebuilds the file's `waves` array from scratch every
run — candidates are `polls.json` rows for the **HOUSES** list
(`YouGov, DemosAU, RedBridge/Accent, Resolve`) dated ≥ FIRST, re-read from their
sources. A wave you hand-edit into the JSON for any other pollster (or any
hand-typed correction) is **silently dropped** by the next weekly
crosstabs-update run: no error, no conflict, the array just regenerates without
it. Hand data lives in the GENERATOR, not the JSON. (Same family of trap as
index.html vs its sources — check whether a `data/*.json` file has a generator
header before hand-editing: demographics.json's `_about` says "Built by
.build/demographics.mjs".)

Which side of the fence the given wave is on: hand-entry constants are for houses
OUTSIDE HOUSES with sporadic tables. A one-off wave from a HOUSES member whose
source IS machine-readable goes through the reader instead — e.g. the Sky News
Pulse 27 Jan 2026 YouGov crosstab (commit 40e3d43): KNOWN_IG id + a committed
ig-fixtures page + a test-crosstabs pin + FIRST_EXTRA to admit the pre-FIRST date.
That path files the wave with parser tests a hand-typed constant never gets — see
auspol-demographics-reader ("YouGov chart ids and sheet variants" and its 27 Jan
worked case).

## The durable recipe (worked 2026-09-30, commit ad87338)

Roy Morgan release 10363 (Sep 29) was the first release ever to publish its
"Primary Vote by State" table (earlier 2026 releases gate it behind "contact
Julian McCrann" — see roymorgan-release-extraction for the 35-release crawl
that proved it). One wave, format unproven → hand-entry, NOT a new extractor.

1. **Constant** in `.build/demographics.mjs` after `KNOWN_DROP`, keyed by the
   poll row's `date` (field-end Sunday, not release day — 10363's wave is
   `2026-09-27` even though the release is dated the 29th), holding `source`
   (the PDF URL — S3 `roymorgan-cms-prod…`), the `state` dims, and a `total`
   block for the gate. Shares as printed.
2. **Push block** after the main candidates loop (before the Resolve block):
   per entry, skip if already on file (unless `--refresh`); find the poll row
   by `pollster + date`; **`pend()` — never silently skip — when the poll row
   doesn't exist yet** ("no Roy Morgan poll row for this wave's date yet"), so
   an entry filed before its wave lands stays visible, and `pend` also keeps
   any older on-file row.
3. **Same gates as machine-read tables**: `dimsProblem(dims)` (shares 0–100,
   sum 100±5) and `totalProblem(h.total, p)` (all-voters column vs the poll
   row's primaries ±1). A hand-typed table runs through them too — the gate is
   exactly what catches a transcription slip; a failure lands the wave as
   pending with the reason, nothing is written.
4. **Row fields from the poll row**, not retyped: `dateStart`, `sample`,
   `article: p.url`; `source` = the constant's PDF URL; `read: "published
   table"` (the existing vocabulary — `measured from the charts` is DemosAU's).
   Party key order `alp, lnp, onp, grn, oth` to match YouGov waves.
5. **Header house-note**: add the house to the "Runs itself…" comment block in
   the generator header with the whole story (which release, that most waves
   carry no table, why not in HOUSES) — the next person greps the header.
6. **demo-groups.mjs comment**: extend the `state` set's comment with what this
   house prints and which groups it joins.

## Keep the house OUT of HOUSES

`HOUSES` drives both alarm checks, and both misfire on a house where MOST
waves have no breakdown:

- **stale**: every `HOUSES` poll older than `STALE_DAYS` (16) with no wave on
  file and no `KNOWN_SKIP` is listed `stale` → the weekly run FAILS. Roy
  Morgan polls weekly; ~all of them have no state table → perpetual red.
- **dropped**: a group printed in two waves running then missing from the
  house's NEWEST wave alarms. Sporadic tables trip it constantly.

Spelling the pollster name in the constant's keys (`"Roy Morgan|" + date`)
keeps it in the output without enrolling it in the watchdogs. If the format
later proves recurring (watch the next release, ~Oct 6/13 2026 for Morgan),
THAT is when you build the reader into/beside `extract-roymorgan.mjs`, move
`ROYMORGAN_STATE`'s entries over, and consider HOUSES membership.

## harmonize() and the same-people rule

- Morgan's labels (`NSW`, `Vic`, `Qld`) already match DEMO_SETS keys —
  `harmonize()` needed NO edit. Check label spelling against `DEMO_SETS`
  groups before touching the mapper; label case matters (`Vic` ≠ `VIC` —
  YouGov's uppercase needed its `ygGroup` normaliser, Morgan's didn't).
- **SA and WA were stored on file but join nothing**: the state set's
  "Rest of Australia" is formed either verbatim (Resolve) or by merging a
  house's full minor-region cut at known population weights (YouGov's
  SA+WA+ACT/NT/Tas). Morgan prints no Tas/ACT/NT cut, so NO rest group can be
  formed — never fabricate one as a residual of the national total (that
  group's pooled average would silently mix bases). Groups that can't join
  still belong in the JSON verbatim: `_about` promises "groups kept exactly
  as each house draws them".

## Newspoll quarterly aggregates (NEWSPOLL_DEMO) — recurs every quarter

NEWSPOLL_DEMO in `.build/demographics.mjs` is the long-standing constant for
the QUARTERLY pooled Newspoll demographic releases ("Newspoll (pooled)" NO_AGG
rows in polls.json). Worked three times in 2026: 2026-03-26, 2026-06-26
(a5822c6), 2026-09-18 (39ad785). Unlike a Morgan one-off, this one RECURS —
expect another wave each quarter — so the source ladder matters more than the
entry mechanics.

### Source ladder per quarter (it moved between quarters)

1. **Article Infogram embeds** — but a quarterly article carries MULTIPLE
   `embed-infogram` divs (Q3 2026 had four; Apr–Jun had one). Position in the
   prose is only a weak hint and the demographics-prose candidate can be the
   WRONG chart: Q3's embed placed after the all-demographics sentence carried
   Albanese SATISFACTION (Satisfied/Dissatisfied/Uncommitted over the same
   nine sheets), while the primary-vote table (`_/8Tko917VckLB6BkkGNwe`) sat
   right after the by-STATE paragraph. Dump EVERY `_/<id>` from
   `https://e.infogram.com/_/<id>?src=embed` and read sheet 0 — the primary
   table's State sheet rows are party names; anything else, keep looking.
   Parse with `.matilda/scratch/dump-embed.mjs` (argv-generalised
   npq-parse.mjs; `CHART` entities → `props.chartData` → `sheetnames`+`data`
   grids, prints every sheet). The primary embed reports 9-10 dims incl.
   Housing from Apr–Jun 2026 on.
2. **Open full-tables PDF** — some quarters The Australian links "Full tables"
   to `origin.theaustralian.com.au/wp-content/uploads/<yyyy>/<mm>/newspoll…`
   (Q1 2026: `…/2026/04/newspoll5april2026.pdf`, no auth needed; the PB
   thread's "UPDATE: Full tables here"). `pdftotext -layout`; PRIMARY VOTE
   prints as a 26-group column block (ALL + states + gender + age + education
   + income + working + language + religion), one line per party.
3. **Wikipedia's subpopulation page** — NOT guaranteed. It carried the Q2
   2026 quarter but NOT Q1 or Q3 2026. Never write "Wikipedia agrees" in a
   per-wave comment until you've fetched and verified; when absent, the entry
   is verified single-source (PB-prose checkpoints + row sums), and the
   comment says so.

### Verification ladder (it has caught things)

- Every printed group's five shares sum to 100 (incl. the ALL column).
- PB-thread prose checkpoints: per-state leads (Qld 25/19/12/36…), and
  PRINTED CHANGES reconciled against the PREVIOUS committed NEWSPOLL_DEMO
  entry ("renters Labor down 8, 35→27" must equal that entry's `Renting`
  figure) — type the change's from/to values from your committed table, not
  from the prose.
- Then `node .build/demographics.mjs`'s own `totalProblem` gate compares the
  ALL column to your new polls.json row's primaries ±1.

- Label tidying per the existing 2025/06 entries: Male/Female→Men/Women,
  age-band hyphens→en-dashes, "TAFE / College"→TAFE, "<$50k"→"Under $50k",
  "$50k - $99k"→"$50–99k", "Owned Outright/Owned with Mortgage/Rented"→
  "Own outright/Mortgage/Renting". Keys stay `alp, lnp, grn, onp, oth`.
- Entry is date-keyed by fieldwork END and sits in NEWSPOLL_DEMO in date

### The polls.json row goes with it

The pooled wave itself is a NO_AGG `"Newspoll (pooled)"` row: `date` =
fieldwork end, `dateStart` = window start, `published` in AEST local clock
(as the article's `datePublished` Z time converts; `T19:00`/`T20:00` seen),

## Roy Morgan's prose 2PP packs (ROYMORGAN_TPP → dimsTpp, stages 1–2, 2026-10-09)

dimsTpp is the pipeline's first 2PP-by-group field: respondent-allocated
`{alp, lnp}` pairs per group, hand-entered from release prose. 17 waves —
nine 2PP-only packs (May–Oct 2025, Jan/Feb 2026 specials) where the finding
predates the primaries tables, and eight layered onto ROYMORGAN_DEMO keys
(Nov/Dec 2025, weekly Apr–May 2026). Never cite `tpp_flows`: the by-group
paragraphs ride the respondent national, never the 2025-flows figure the
release quotes alongside it.

### Schema and gate

- `ROYMORGAN_TPP` keyed by poll-row date: `{source, total, dimsTpp}`.
  `total` is the release's printed NATIONAL respondent pair — check-only,
  never emitted (a primaries `total` IS emitted; don't conflate).
- `dimsTppProblem(dimsTpp, total, poll)` (crosstab-parse.mjs): pairs 0–100,
  alp+lnp ≈100 (>0.6 trips; hung pairs like 50/50 must still sum), national
  vs the poll row's tpp_alp/tpp_lnp — **trips only >1**, so a printed total
  exactly 1.0 off the poll row PASSES. That edge is why finding 9956 files.
- Merge nests `.tpp` onto existing ROYMORGAN_DEMO keys; a wave may carry
  dims, dimsTpp, or both. `read` = "published prose" iff no dims, else
  "published table". gen-data §7g and demo-groups ignore dimsTpp entirely —
  the field is stored-only until the pooling/display stages land.

### Inventory first, transcribe second

1. Cache each candidate finding page under /tmp; parse `__NEXT_DATA__` →
   `postBy.blocks[].saveContent`, strip tags, grep paragraphs mentioning
   two-party + a group word. Weekly 2026 findings print gender+age 2PP in
   prose (some also in a printed table row); **state 2PP splits print only
   in monthly/4-week-pool findings** — Nov and Dec 2025 are the only ones
   that exist anywhere.
2. Read the POLL ROW (polls.json tpp_alp/tpp_lnp, n, dateStart) before
   writing anything: its basis (weekly vs four-week pool) decides which
   printed tables belong to it.

### The pool-vs-row adjudication rule (the load-bearing part)

An entry's printed national pair must reconcile with the poll row's
respondent 2PP inside the guard; that's the wave filter.

- **2025-11-16 (9951)** — poll row IS the Nov four-week pool (56.5/43.5) →
  clean; full state×6, gender, age×4.
- **2025-12-14 (9956)** — row is the mid-December WEEK (54.5/45.5) but the
  release's by-group tables are the December four-week POOL (printed
  national 55.5/44.5, |Δ|=1.0 → inside tolerance). Filed, because the
  wave's ROYMORGAN_DEMO primaries already came from those same pool tables
  (entering pool-2PP beside pool-primaries is the consistent choice).
  Documented in the ROYMORGAN_TPP header comment.
- **2026-02-01 (9971)** — row is the early-Feb week (56/44); the finding
  prints only its January four-week pool (54.5/45.5) → 1.5pt, PAST the
  tolerance. NOT entered — the user adjudicated skip, refusing the
  "enter without a printed total" escape hatch (a check-total is the
  point of the entry). The exclusion is written into the generator header
  comment and the test comment so no sweep relitigates it.
- Weekly Apr–May 2026 (10178–10218, six waves) — the by-group 2PP pairs
  print in that week's own prose and match the weekly row exactly → clean.
  Two findings (10187, 10191) also print a by-group Two-Party Preferred
  table row; prose and table must agree. 10191's weekly table HEAD
  misprints the week label twice ("Apr 6-12" x2) — the group rows are this
  week's; misprint noted on the entry.

### Misprint resolution (four releases so far)

## The fold-wave case: a party the table folds away stays ABSENT, never zero (worked 2026-10-09, commit e04f7f0)

### The backing dataset beats the pasted table

The user's paste was itself defect — the 65+ Greens cell was missing. Before

the article's Datawrapper chart exposes its CSV at
`https://datawrapper.dwcdn.net/<chart-id>/<version>/`
(FexJm/2 here); it held the missing cell (65+ grn = 1) and became the

### Null fidelity: the contract and every consumer that needed it

The four-party table folds One Nation into Others — the wave has NO onp
share. The contract: the party key is emitted ABSENT (null) end-to-end.

- null says "not printed"; a 0 says "printed 0" — real data (DemosAU's
  School row prints a genuine 0; its pin now asserts the pair, null vs 0).
- Filing 0 for a folded party INVENTS a share §7g pooling would average in
  as real; filing nothing for all-future readers mixed the bases silently.

Consumers/gates taught the distinction in the same commit (the audit list
for any future wave that shrinks a party away — a wave ADDING a party never
needs this, its older keys were already null):

- `demo-groups.mjs` harmonize `put()`: keep null keys
  (`sh[k] == null ? null : (+sh[k] || 0)`) — `||0` alone folds null→0.
- `gen-data.mjs`: `demoNorm` and the DEMO_BY_POLL `v`/`t` emitters map
  nulls through; §7g pooling `continue`s on a wave missing a party; the rug
  payload rebuilds waves by IDENTITY (dates alone collide).
- `rd-panels.jsx`: group-scatter, `chartsFor` month-dot sum (`a+(b||0)` +
  filter), WvRug dodge/ring/render all guard null before the map/sort.
- `rd-allpolls.jsx`: the demographics facet's All-voters row prints an
  em-dash for a null cell instead of `Math.round(null)` → 0.
- The `sharesProblem`/`dimsProblem`/`totalProblem` gates are null-safe
  already — "polled figures the table folds away are no defect".

## Recovering a wave whose HOUSE SOURCE NEVER EXISTED (worked 2026-10-09, commit 75f3517)

### The source ladder when the house has nothing

1. **Wikipedia's "subpopulations" chapter** of the next-election polling
   article transcribes the tables (four generation tables here), each
   citing the publisher's article; a row may carry a second citation
   (Kos Samaras's protected tweet backed the Gen X row — visible to
   Wikipedia editors, not to us). A transcription is a STARTING POINT,
   never the filing itself.
2. **Anchor the transcription against the publisher's own prose** — re-read
   the paywalled article WHOLE through the chrome-session-piggyback
   (outerHTML dump works on AFR) and find cells the prose quotes verbatim
   ("the Coalition's primary support among Gen Z voters is 10 per cent and
   23 per cent among Millennials"). Every verbatim cell that matches the
   transcription anchors the whole table; two matched here.
3. **Anchor against the committed poll row's fold evidence**: this wave's
   IND column printed "N/A" everywhere and the poll row has `ind: 11,
   oth: null` — the house folds independents into Others, so file the
