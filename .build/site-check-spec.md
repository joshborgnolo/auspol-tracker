# The deployed-site check (spec)

Drafted 2026-09-01. A watchdog for the one stage of the pipeline that has no
witness: what auspoltracker.com actually serves.

## Why

Every other stage is watched. Extractors have guards and `*_STATUS` lines,
`data/polls.json` has `validate.mjs`, coverage has an independent Wikipedia
witness, the next-polls projection now has `np-score.mjs`. Then the wrappers run
`build.mjs`, check its exit code, commit and push — GitHub Pages builds, and
**nobody looks at the result**. A page that builds cleanly but serves stale
bytes, or references an asset that was never emitted, or throws on load, ships
silently. The site is the product; it is the least-watched artifact in the repo.

## What is deployed

`CNAME` → **auspoltracker.com**, GitHub Pages, workflow "pages-build-deployment"
(typically 20–30 s after a push to `main`).

Served from the repo root:

| path | notes |
|---|---|
| `index.html` | ~1.19 MB, single file, all JS/CSS inlined |
| `auspol-polling.html` | secondary page |
| `feed.xml`, `sitemap.xml`, `robots.txt` | generated by `build.mjs` |
| `assets/fonts/*.woff2` | **content-hashed** filenames |
| `assets/cycle-source.<hash>.json` | **content-hashed**, fetched at RUNTIME |
| `assets/auspol-card.png`, `.json` | social card, redrawn best-effort |

Two properties drive the design. Everything except the hashed assets is inlined,
so `index.html` is almost the whole product. And the hashed assets are referenced
by name from inside `index.html`, so a rename that doesn't emit the file is a
runtime break that no amount of HTML inspection reveals.

## The core invariant

**Deployed bytes must equal committed bytes at the deployed commit.**

Do NOT re-derive expected values (poll counts, the "Updated" date) from
`data/polls.json`. That would reimplement `gen-data.mjs` and create exactly the
mirror-drift this repo has just spent effort deleting. The committed
`index.html` IS the expected value; compare hashes.

## Trigger

Two entry points, for two different failures:

1. `on: workflow_run:` for **"pages-build-deployment"**, `types: [completed]`
   — catches a bad or missing deploy immediately after it happens.
   **Check out `${{ github.event.workflow_run.head_sha }}`, not `main`.** The
   comparison is only meaningful against the commit that was actually deployed;
   main may have moved on (it does, often — this repo takes concurrent pushes).
2. A daily `schedule` backstop against `main`'s head — catches what a deploy-time
   check cannot: TLS expiry, DNS breakage, Pages silently reverting, a CDN
   serving a stale object long after a green deploy.

## Checks, in order

1. **Reachable.** `GET https://auspoltracker.com/` — 200, `text/html`, non-empty.
   Any network failure is *inconclusive*, never a defect (see exit codes) —
   except on the scheduled daily backstop, where nothing is deploying and
   unreachability has no benign explanation: there it is a defect.
2. **Freshness / integrity.** sha256 of the response vs sha256 of `index.html`
   at the checked-out SHA. On mismatch, retry with backoff for a grace window
   (~5 min on the `workflow_run` path, since Pages is asynchronous). Still
   mismatched at the end of the grace window ⇒ defect. Report the byte length of
   each and the offset of the first differing byte — that one number turns
   "something is wrong" into a diagnosis in seconds.
3. **Referenced assets resolve.** Extract every `assets/...` reference from the
   DEPLOYED html (fonts, `cycle-source.<hash>.json`, the card) and `GET` each:
   200 and non-zero length. This is the check the hash comparison cannot do —
   `index.html` can be byte-perfect while a hashed asset it names was never
   emitted. `cycle-source` matters most: it is fetched at runtime, so its absence
   breaks a whole tab while the page still loads. Extraction reads QUOTED
   contexts only (attributes, JS string literals, css `url()`) — a source
   comment in the deployed page merely mentions `assets/np-project.js`, a file
   inlined by design, and a bare-text match once fetched a 404 on it. And the
   og card's reference carries a `?v=<date>` cache-buster, so references are
   captured and fetched query-string and all.
4. **The other served files** — `feed.xml`, `sitemap.xml`, `robots.txt`,
   `auspol-polling.html` — same hash comparison, same grace.

Deliberately NOT checked here: whether the data is current or a wave is missing.
`check-coverage.mjs` owns that with an independent witness; duplicating it would
give two sources for one verdict.

## Exit codes

Follows `coverage-doctor.mjs`, not `check-coverage.mjs` (whose `3` means
"actionable gap" — do not reuse it):

- `0` — deployed bytes match and every referenced asset resolves.
- `1` — **inconclusive**: the site could not be reached, DNS/TLS failed, or the
  grace window expired while Pages was still building. A watchdog that cries
  wolf gets muted; an unreachable host is not proof of a broken build *while a
  deploy may be in flight*.
- `2` — **defect**: content mismatch after grace, a referenced asset missing,
  or — on the scheduled daily backstop only — the site unreachable. The
  backstop runs when nothing is deploying, so DNS/TLS/reachability failure
  there has no benign explanation and must not go green.

Last stdout line: `SITE_STATUS {json}` carrying `{verdict, url, sha, liveBytes,
localBytes, firstDiffAt, assets:{checked,failed:[]}}`.

## Traps

- **A dirty working tree makes this lie.** Verified 2026-09-01: local
  `index.html` differed from the live site by 31 bytes, which looked like a stale
  deploy and was actually an uncommitted rebuild from a concurrent session. CI's
  clean checkout avoids it; anyone running the script locally must check
  `git diff --quiet HEAD -- index.html` first and refuse otherwise.
- **So does committed-but-unpushed work.** Pages builds `origin/main`; a local
  HEAD one commit ahead compares against bytes that were never deployed and
  reads as class 2. Local runs refuse on `origin/main..HEAD` non-empty, with
  the same class 1 as the dirty tree — push, then re-run.
- **Pages is asynchronous.** Without the grace window this check fails on every
  deploy it is meant to verify.
- **`main` moves during the run.** Hence pinning to `workflow_run.head_sha`.
- **Do not diff rendered text.** The page is React-rendered from inlined data;
  scraping visible strings would couple the check to copy that changes for
  editorial reasons. Bytes and asset URLs only.

## Optional second phase: a runtime smoke test

Only worth adding once the byte check is boring. `poll-agent.yml` already
installs `puppeteer-core` best-effort with `CHROME=/usr/bin/google-chrome`, so
the infrastructure exists. Load the deployed URL headless and assert: no
uncaught exceptions, no failed network requests, `#root` (or the app's mount)
has non-trivial content, and the four tab labels are present. Keep it a separate
exit class from the byte check — a rendering fault and a stale deploy need
different responses.

## Verification recipe

- Point the script at the live URL on a clean checkout of `main` — expect `0`.
- Break it deliberately three ways and confirm each is caught and correctly
  classified: (a) compare against an older commit's `index.html` ⇒ `2` with a
  sensible `firstDiffAt`; (b) rename a hashed asset reference in a local copy of
  the deployed html ⇒ `2` naming that asset; (c) point at a nonexistent host
  ⇒ `1`, never `2`.
- Confirm the grace window by running it immediately after a push, before Pages
  finishes: it must retry and then pass, not fail.
