# /vic/ — the main-page standard

This document is the vic-polish reviewer's yardstick: what "up to the
standard of the main page" means for the Vicpoll satellite
(`vic/index.html`, generated by `.build/refresh-vic.mjs` from
`data/vic-polls.json`). The main page (`index.html`, rd redesign) is the
reference; this doc says **which** of its conventions the satellite must
share, and — just as important — which differences are LOCKED product
decisions that must NOT be flagged as gaps (§4).

Sources of truth while auditing: this doc first; then the skills
`.matilda/skills/auto-skill-auspol-vic-satellite-plan/SKILL.md` (locked vic
decisions) and `.matilda/skills/auto-skill-auspol-satellite-page-branding/
SKILL.md` (the shell contract); then the code itself
(`.build/newtracker/template.html` for main-page CSS conventions,
`.build/refresh-vic.mjs` for what the page is meant to render).

## 1. Shell & chrome — machinery, never copies

The vic page carries the site shell like every satellite. These parts are
LIFTED from the main page by `.build/site-shell.mjs` and are auto-protected
by existing gates (`node .build/site-shell.mjs --check`,
`.build/test-site-shell.mjs`, the masthead-parity probe):

- Split lockup (wordmark link + dial glyph link to `/#story`), the
  three-fact status block and phone compact line, the lifted tab bar
  (Now / Past cycles / All polls / Info linked to `/#<view>`), the
  colour-theme switch (shares `localStorage auspol.tweaks`), the live 2PP,
  the colophon, the tide band.
- Frame geometry: page content sits inside `.sh-frame`, whose
  `--sh-gutter`/`--sh-maxw` mirror the main page's `--rd-gutter`/
  `--rd-maxw`. Page-owned content must observe that frame — nothing pokes
  past it, nothing invents its own margins.

**A gap here is OUT OF SCOPE for the builder** (the shell is owned by the
main page). Report it with ev so a human can take it to
`.build/site-shell.mjs`; do not ask the builder to fork shell chrome.

## 2. Visual / layout parity (user-visible, not implementation)

The vic page is vanilla-JS SVG (atlas precedent), not the main page's
React TrendChart engine. Judge the USER-VISIBLE behaviour, not the
implementation:

- **Type & copy conventions.** Headings are sentence case in source
  (all-caps only ever via CSS `text-transform`); Australian spelling;
  figures use U+2212 minus, never hyphen-minus; date labels follow the
  main-page style ("28 Nov", "24–29 Sep"); numerals align
  (figure-bearing columns right-aligned in tables).
- **Dark mode is whole.** Every visible colour rides a token or a
  `prefers-color-scheme` rule — no hardcoded hex that renders unreadable
  dark. Spot-check by forcing `sh-dark` on `<html>` and reading key
  figures/labels.
- **Phone rung.** At 390px and 320px there is no horizontal overflow
  (nothing extends past the viewport width); tables, charts and the poll
  table remain legible — collapse or scroll internally rather than
  squeezing to mush. The main page's phone treatment swaps rows for
  cards; the vic page must at least not break.
- **Charts carry the main page's honesty affordances**: per-release dots
  (one per published wave, per house), a visible trend line that never
  pretends to be data, axis labels/ticks that say the scale, and a hover
  or tap affordance naming a point's value (main page: TrendChart
  tooltips; vic may be simpler but must exist for head figures).
- **Numbers are live.** Every displayed figure derives from
  `data/vic-polls.json` at generation time — no hardcoded topline in the
  template that can go stale between polls (the generator-composes/page-
  renders split; `refresh-prediction.mjs` precedent).
- **Footer method note** reads as prose like the main page's MethodNote,
  with the sections: how the headline blend is made · why two-party is
  published-only · where the numbers come from (provenance credit +
  estimates-only disclaimer).

## 3. Feature parity — what a competent tracker page carries

The vic page's section spine (each verified against the rendered page):

- **Two-party preferred**: headline current estimate with its date basis
  ("from N published 2PPs ending <date>"), trend chart vs the 2022
  baseline line (ALP 55.0), per-house dots.
- **First preferences**: 5-way ALP/LNP/ONP/GRN/OTH treatment — Victoria
  2026 is a five-way race; anything fewer is a gap. Per-house dots,
  same recency weighting.
- **The leaders**: preferred-premier (preferred leader) series AND
  satisfaction/approval splits where published, leader-change eras
  handled (Andrews→Allan→Carroll; Pesutto→Battin→Wilson) — a leader
  change must not smear two eras into one line.
- **Poll table**: every published poll, newest first, with pollster,
  fieldwork dates, sample (em-dash when unpublished — absent data is
  never invented), the 2PP/primaries, and a source link per row.
- **Freshness**: the page visibly ages ("latest wave ended <date>" or
  the generator's updated stamp), like the main page's masthead status.
- **Next expected polls** (stretch item from the landing plan): a
  cadence-projection strip may be absent without being a gap — file it
  only as an aspiration once everything else above the line passes.

Keyboard/ARIA hygiene where the page adds interactive controls:
focusable, `aria-pressed`-style state, labelled groups (theme switch
precedent in the shell).

## 4. Data & estimates — the locked vic decisions (§ never-flag list)

These are deliberate, user-locked divergences from the main page. The
reviewer must NOT file them as gaps:

- **Published-2PP-only headline blend.** No flows-implied 2PP anywhere
  (no 2022 ONP lower-house baseline exists — false precision). If
  displayed figures ever go flows-implied, THAT is the gap.
- **No house-effect adjustment** and **≤6 waves per house** in any
  window. Recency weight `n·2^(−d/28)`, 60-day headline window widened
  until ≥3 published 2PPs, 120-day trend window, `SAMPLE_DEFAULT=1000`.
  Don't relitigate the constants; flag only a page that displays numbers
  inconsistent with them.
- **Data-legitimate nulls stay null.** `onp: null` on pre-ONP-fielding
  waves, null PPM values a house never published (wiki `{{N/A}}`).
  Never "fix" a row in data to satisfy a check — if a check is wrong,
  the check learns the null is legal.
- **Provenance is honest**: `provenance` arrays name where a row came
  from (`electiontracker`, `wikipedia`, extractor, `hand`); a row must
  not claim verification it doesn't have. `sourceUrl` present wherever
  a published source exists. Wikipedia-derived rows must not carry
  wiki-estimated 2PP as published (published-source rule).
- **Leader-keyed schema**: leaders are keys (`carroll`, `wilson`,
  `pickering`…), eras are pairs like `carroll-vs-wilson-vs-pickering`;
  the governor/premier name changes are eras, not new pollsters.
- **Display name "Vicpoll"** with the URL `/vic/` — never "VicPol"
  (the police collision). Kicker/title say Vicpoll.

## 5. Orphan scope — what must NOT change

- The vic page is **unlisted**: nothing on the main page (template.html,
  tab bar, footer, copy) links to it; it adds no entry to `feed.xml`
  (federal stays federal). Any commit touching main-page sources to
  link/promote the satellite is out of scope.
- Shell changes (masthead, tabs, colophon, footer) belong to
  `.build/site-shell.mjs` + the main page — file as a gap for humans,
  do not fork locally.
- The loop's own kit (orchestrator, probes, prompts, this doc) is
  human-owned.

## 6. How to audit (procedure for the reviewer)

1. Read `.build/probe-vic-standard.mjs`'s pack (`auditPack` path in your
   round context) — 40 mechanical checks + inventory. Any FAIL is an
   evidence-backed candidate gap.
2. Walk the rendered page markup (`vic/index.html`) for §2–§3 items the
   pack can't judge: hierarchy, spacing rhythm, hover affordances,
   phone-rung integrity, copy quality, table completeness.
3. Cross-read `data/vic-polls.json` and `.build/refresh-vic.mjs` for §4
   data truths (constants, provenance, nulls, eras).
4. Compare against the main page's current conventions in
   `template.html`/`index.html` ONLY for the conventions §1–§3 name —
   do not mine for extra ideas. Flag departures from THIS doc and the
   main page's conventions, not opportunities for new features the main
   page itself hasn't set.
5. File each gap ONCE under a STABLE id (kebab-case, e.g.
   `tpp-no-hover`, `table-missing-sample`), with evidence = file:line,
   a selector + measured value, or a pack check id. Re-open rather than
   duplicate: an id means the same gap forever.
