# /vic/ — the main-page standard (strengthened 2026-10-04; interaction tier added same day)

The vic-polish reviewer's yardstick: what "up to the standard of the main
page" means for the Vicpoll satellite (`vic/index.html`, generated by
`.build/refresh-vic.mjs` from `data/vic-polls.json`). The main page
(`index.html`, the rd redesign) is the reference. This version replaces a
checklist-lite doc that let a reviewer pass the page on hygiene alone: §2–§3
are now a DEMAND LIST. Every numbered item (D1…) must hold, verified by the
probe (`node .build/probe-vic-standard.mjs`) where mechanical and by reading
the page + `.build/refresh-vic.mjs` otherwise. Anything §7 (aspirations)
may be absent without costing a pass.

Sources while auditing: this doc first; then the skills
`.matilda/skills/auto-skill-auspol-vic-satellite-plan/SKILL.md` (locked vic
decisions) and `auto-skill-auspol-satellite-page-branding/SKILL.md` (shell
contract); then main-page conventions in `.build/newtracker/template.html`
(the rd-redesign CSS vocabulary, §2's reference).

## 1. Shell & chrome — machinery, never copies

Lifted by `.build/site-shell.mjs`, auto-protected by existing gates (shell
`--check`, `test-site-shell.mjs`, masthead-parity probe): split lockup, the
three-fact status block + phone compact line, lifted tab bar, colour-theme
switch (shares `localStorage auspol.tweaks`), live 2PP in the masthead, the
colophon, the tide band, plus the `.sh-frame` geometry (page content inside
the same gutter/max-width as the main page). A gap HERE is out of scope for
the builder (shell-owned): report it in notes for a human, never demand a
local fork.

## 2. Chart demand list — the main page's trend-chart vocabulary

The vic page is vanilla-JS SVG (atlas precedent), not the React TrendChart
engine. Judge the USER-VISIBLE vocabulary, not the implementation. EVERY
chart on the page must carry all of these (D-items: a missing one is a
file-able gap):

- **D1 Per-wave dots, full telemetry.** One dot per published wave, per
  house, and every dot's hover `<title>` carries the full record: firm
  name, the fieldwork SPAN (condensed main-page date style), and the
  value(s) it plots. Where the house published a sample, the sample rides
  the title too (`· n=1,234`). A title that names only firm/date/value is
  short of the main page's tooltip telemetry.
- **D2 End-of-line value labels.** Every series carries its current value
  at the right edge of the plot (main-page end labels), not only axis
  legend: 2PP chart = both majors' current estimates; first-preferences
  chart = all five series (ALP/LNP/ONP/GRN/OTH); leaders charts = every
  leader series shown. (The 2PP chart already does the ALP figure — the
  convention is per-series, not per-chart.)
- **D3 Official-result markers.** Where an official result exists on the
  chart's domain, it is plotted as a labelled marker: the 2PP chart's 2022
  baseline (`2022 election: Labor 55.0`) is the model. The first-
  preferences chart must carry the equivalent 2022 election marks for the
  parties (official VEC lower-house statewide primaries), labelled
  `2022 election`. The leaders charts carry no baseline and need none.
- **D4 Era boundary markers.** The leaders charts plot patience-era
  boundaries: premiership changes (Andrews → Allan → …) and opposition-
  leader changes (Pesutto → Battin → …) as labelled vertical ticks, the
  main page's event-marker convention. Lines must not smear two eras into
  one continuous series (era split is already locked data design — this is
  the visible boundary marker).
- **D5 Axes that say the scale.** Y ticks with values, x ticks with
  month-year labels across the full window, U+2212 minus on negatives
  (net charts), an explicit plot-edge marker for election day
  (28 Nov, as now), and no hardcoded-hex strokes that die in dark mode
  (all paint via tokens / currentColor).
- **D6 Legend naming series.** A legend row naming every series the chart
  draws (current dot+name legend is the model), one swatch colour per
  series, share of the page's token set.

### Interaction tier — the main page's chart BEHAVIOUR vocabulary

The user-visible asks above are only half of "in line with the main page";
the main page's charts behave: they hover with rich cards and their dots
act as entry points into the poll archive. The vic page answers in its own
vanilla-JS vocabulary (no React, no external assets) but the behaviour is
demanded, not aspirational:

- **D14 Custom hover cards on every wave dot.** Hovering (or focusing,
  or tapping on touch) any plotted dot floats a tooltip CARD near the
  dot carrying the full wave record: firm, fieldwork span, the plotted
  value(s), published sample, and on leaders charts the leader/era name.
  One shared card per figure (or per page) populated at generation
  time, shown/hidden on pointer enter/leave, pinned on tap until the
  next tap elsewhere. The native `<title>` (D1) remains as the no-JS
  fallback; a page whose only tooltip is `<title>` is SHORT of this —
  the main page's hover surface is the custom card, not the browser's.
- **D15 Dots wired to the poll table.** The voting-intention dots and
  the "Every published poll" table rows share a wave key: every dot
  carries a `data-wave="Firm|fw-end-date"` attribute (any equivalent
  wave-key scheme), every table row carries a matching anchor `id`, and
  clicking/hovering a dot scrolls to and highlights its row (smooth
  scroll, the main page's scroll-to-section convention; highlight via
  CSS class). JS enhances only — the no-JS page must keep every dot,
  row and `<title>` it has today.
- **D16 Leaders charts are first-class interactive.** The preferred-
  premier and approval/satisfaction figures join D14/D15 wholesale:
  hover cards on every leader wave dot (leader, fieldwork span, value,
  sample where published), era-boundary ticks (D4) respond to hover
  with the change description (who replaced whom, on what date).

## 3. Page-structure demand list

Section spine stays as shipped (locks §1's spine), plus ONE addition
from this tier: hero duo → next-polls strip (D17) → Two-party
preferred → First preferences → The leaders → Every published poll → the
three method notes. On top of that spine, each section must carry:

- **D7 Hero duo, main-page grade.** The headline pair (current 2PP figure,
  countdown-to-election figure) in the hero type treatment (serif,
  large) with a clause line under each naming its basis: the 2PP figure
  names the blend window and house count ("from N published two-party
  figures …"); the countdown names the fixed date. Beside them a delta
  statement against the only honest baseline: the 2022 election result
  (e.g. how far the current 2PP blend sits from 55.0 / 45.0).
- **D8 Section dek.** Every section (each of the four content h2s) opens
  with a one-sentence gist dek naming the section's headline finding
  (the main page's lead+dek convention), not a bare label.
- **D9 Freshness visible.** A "latest wave ended <date>"-style line near
  the top of the page (vp-latest pattern, as now) plus the generator
  stamp — the page must visibly age.
- **D10 Pollster chips.** The houses currently windowed, with swatch
  colours consistent with the chart dots (as now).
- **D11 Poll table, complete.** Every published poll row, newest first,
  columns: pollster/firm (+client note), fieldwork span (condensed
  style), sample (em-dash when unpublished — absent data never invented),
  2PP and/or primaries as published, outbound source link per row. The
  table's row count equals the census in `data/vic-polls.json` — the
  h2 says "Every published poll" and the page must keep that true. A
  caption or footer line states the count and window.
- **D12 Phone rung, main-page pattern.** At 390px and 320px: nothing
  wider than the viewport (no document-level horizontal scroll); the
  poll table converts to a card/rows layout or an internal horizontal
  scroll strip — either main page pattern is acceptable, squeezing the
  table to mush is not; figures stack; charts downgrade in width only;
  the theme switch stays reachable.
- **D13 ARIA hygiene on page-owned parts.** Every chart figure carries
  role="img" + an aria-label stating what it plots and the current readout;
  the poll table has a <caption>; interactive page additions (if any)
  are focusable and aria-pressed/state labels set.
- **D17 Next-expected-polls strip.** The main page's Next-polls
  predictor machinery, in vic vocabulary: a strip right under the hero
  carrying one card per house currently windowed, each showing the
  house's median release cadence (computed at generation time from the
  published waves in `data/vic-polls.json`), the projected next
  release date, and an earned countdown or overdue badge ("expected in
  ~9 days" / "3 days overdue"), with the election-day anchor (28 Nov
  2026) named in the strip's subline. Derived, never hand-maintained:
  the dates must move when the data moves.

## 4. Data & estimates — locked vic decisions (never-flag list)

Deliberate, user-locked. The reviewer must NOT file them:

- Published-2PP-only headline blend; no flows-implied 2PP anywhere (no
  2022 ONP lower-house baseline — false precision). If displayed figures
  ever go flows-implied, THAT is the gap.
- No house-effect adjustment; ≤6 waves per house per window; recency
  weight n·2^(−d/28); 60-day headline window widened until ≥3 published
  2PPs; 120-day trend window; SAMPLE_DEFAULT=1000. Flag only a page whose
  numbers are inconsistent with these constants, never the constants.
- Data-legitimate nulls stay null (pre-ONP-fielding onp:null, unpublished
  PPM values, unpublished samples). Never "fix" a row to satisfy a check.
- Provenance honesty: `provenance` arrays name the row's origin;
  `sourceUrl` wherever a published source exists; Wikipedia-derived rows
  never carry wiki-estimated 2PP as published.
- Leader-keyed schema (`carroll`, `wilson`-era keys); era changes are
  keys not annotations.
- Display name "Vicpoll" at /vic/ (never "VicPol").

## 5. Orphan scope — what must NOT change

- The page is unlisted: nothing on the main page links to it; no
  `feed.xml` entry (federal stays federal). Main-page sources are
  builder-forbidden.
- Shell chrome belongs to `.build/site-shell.mjs`; the loop kit, the
  probe, and this doc are human-owned.
- The builder may change ONLY: `.build/refresh-vic.mjs`,
  `vic/index.html` (regenerated, never hand-edited), `data/vic-polls.json`
  (source-URL/provenance corrections only — never new waves or figures
  without an in-repo source), `.build/vic-watch.mjs`, and gitignored
  scratch under `.build/vic-src/`.

## 6. How to audit (reviewer procedure)

1. Read the probe pack (`auditPack` in round context). Any FAIL is an
   evidence-backed candidate gap. The probe mechanically covers D1
   (telemetry incl. sample, for a sample of dots), D2 (per-series end
   labels), D3 (2022 markers incl. first-preference), D4 (era boundary
   marks), D13 (ARIA hygiene), D14 (hover-card signature: tooltip
   styling + host element + pointer wiring), D15 (dot wave-key attrs
   vs table-row ids vs dataset-reading script), D17 (strip presence
   with per-house cards) — check its list before re-deriving.
2. Walk the rendered page + generator for the items the probe can't
   fully judge: phone rung (D12: read the CSS media rules — an overflow-x
   wrapper on the table counts as an acceptable scroll strip only if the
   table itself stays legible at 390px), dek presence/quality (D8, read
   the copy), freshness line position (D9), table completeness against
   the census (D11 — the probe reports both counts), the QUALITY of the
   D14 card content (read the generator's card template against the D14
   record), the D15 click/highlight behaviour (read the page JS — the
   pairing must be wave-keyed, not positional coincidence), D16's
   leader-card content and era-tick hovers, D17's cadence arithmetic
   (spot-check one house's median against the data).
3. Cross-read `data/vic-polls.json` for §4 truths.
4. File each gap once under a stable kebab-case id; re-open rather than
   duplicate. Evidence = file:line, selector + measured value, or pack
   check id.
5. `pass` means: every D1–D17 demand holds (or the probe's pack plus your
   reading vouches for the non-mechanical ones) and no §4 violation was
   introduced. Do not gold-plate beyond D17 — file richer ideas as NOTES.

## 7. Aspirations — never filed as gaps

Worth noting in `notes` when everything else passes, never a gap on its
own: month-average table rows, an archive jump-pill bar, an
og:image share card for /vic/, keyboard shortcuts mirroring the main
page's quick keys, a linked-highlight mode across the three
voting-intention charts.
